# Marketplace Customer Frontend — Audit, Benchmark & Gap Analysis

Date: 2026-09-06 · Branch: `fix/system-check-2026-09-06` · Surface: `modules/marketplace/frontend` (Next 16 zone, basePath `/marketplace`, port 3002) reached through the shell `apps/web` (port 3000), talking to the gateway on 3001.

This document is Deliverables 1–10 of the audit brief. The implementation plan and the P0–P3 task list (Deliverables 11–13) are in `docs/superpowers/plans/2026-09-06-marketplace-customer-frontend-plan.md`. The post-implementation validation report (Deliverable 14) is appended at the end of this file once Phase G has run.

## 0. Method

Everything below was measured on the running dev platform, not inferred from the code alone.

| Step             | What was done                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Static inventory | Every `page.tsx`/`layout.tsx` in the zone (63 routes), every colocated component, the shared packages the zone renders through (`packages/shared-core`, `packages/shared-ui`), and every `api.*` / `apiFetch` / `fetch` call site (123 paths) diffed against the gateway's 213 customer-facing route decorators.                                                                                                                                                                                                                                             |
| API probes       | All 32 public catalogue feeds and 17 authenticated account endpoints called with `X-Region-Code: QA`, with a signed-in seeded customer, and with deliberately wrong inputs (typo search, unknown ids, `?country=IN`).                                                                                                                                                                                                                                                                                                                                        |
| Route sweep      | 61 customer routes (44 anonymous, 21 signed-in) loaded through the shell at 375 / 768 / 1440 px — 195 page loads — recording document status, final URL, title, console and page errors, failed requests, horizontal overflow, `<h1>` count, images without `alt`, controls without an accessible name, unlabeled inputs, sub-40 px touch targets and give-away strings (`Invalid Date`, `NaN`, `Something went wrong` …). Harness: `sweep.mjs` in the session scratchpad (Playwright over system Chrome; results in `results.json`, screenshots per route). |
| Live journeys    | Signed-in: PDP → variant → add to cart → cart → checkout (Qatar address form) → payment → review → place order → order detail → tracking → cancel. Wishlist heart on a listing card, then reload. Country switch via the header picker. Language switch to Arabic. Guest add-to-cart followed by sign-in.                                                                                                                                                                                                                                                    |

Seeded identities used: `testcustomer@kartseek.com` (customer). `DEV_AUTH_BYPASS=true` is on in this environment, so every probe sent an explicit bearer token.
