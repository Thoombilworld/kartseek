# Seller Portal production audit — 2026-09-13

Scope: the marketplace Seller Portal end to end — `apps/web/src/app/seller/**`
(181 pages, 84 under `seller/marketplace`), the shared-core seller client
(`packages/shared-core/src/modules/seller-api.ts`, 1,145 lines), the gateway
seller surface (`seller.controller.ts` 18 routes, `seller-marketplace.controller.ts`
111 routes, `public-sellers.controller.ts` 3 routes, `gateways/seller.gateway.ts`),
the marketplace backend seller service (`src/seller/*`, 105 TCP commands,
`seller.service.ts` 3,750 lines), and the money services it settles through
(payout-service, wallet-service, commission-service).

Method: static census (client→gateway route diff, guard chain, body spreads,
fallback shapes, stub pages) plus reading every money, order, inventory,
registration and real-time path. Live probes are recorded per task in the
plan ledger, not here.

## 2. What already holds (verified by reading, re-proved in T7)

- Guard chain on both seller surfaces: `JwtAuthGuard → RolesGuard → SellerOwnershipGuard → SellerModuleGuard → SellerApprovalGuard`; ownership fails closed on NULL owner; admin branch market-checked; approval cached 30 s and purged by `applySellerDecision`.
- Product approval flow: `approveProduct` activates only the submitter's listing, recomputes the buy box, invalidates catalogue caches, publishes `product.approved` with the index payload; search-service consumes approved/updated/rejected/suspended; public reads gate on APPROVED + active.
- Content edits on an approved product return it to PENDING; attributes validated against the category schema before any write.
- Checkout reserves listing stock conditionally before `place_order`; delivery settles once (repeat refused); commission credited to payout-service's wallet and mirrored to wallet-service's ledger.
- Seller identity on `/seller/*` and `/sellers/me` comes from the JWT subject; the gateway's seller WS connection is authenticated and ownership-checked; Socket.IO runs on the Redis adapter.
- Error filter hides stacks in production and carries `requestId`; CORS origins come from the environment.
